# Source setup

Use a source checkout on macOS. No Windows or Linux build or runtime result is
claimed for this preparation.

## Prerequisites

- A qualified Tachyon compiler supporting the authored Service roles,
  required-provider injection, application-owned collector lifetime and absolute
  `--out-dir` output routing.
- Node.js with the type-stripping support used by the build tools.
- TypeScript `7.0.2`, as declared in `app/package.json`, available as `tsc`.
- Rust and Cargo, plus Apple's Swift compiler and macOS command-line tools.

Compiler binaries, installed dependency trees and build outputs are external
prerequisites. They are not included in the public source inventory. Do not
substitute an arbitrary Tachyon release for the compiler contract required by
this source.

`app/package-lock.json` is generated by npm `10.9.2`, the package manager recorded
in `app/package.json`; TypeScript remains pinned to `7.0.2`. The lock includes its
optional platform packages and registry tarball integrities. It was generated
offline from existing npm registry-cache metadata using Node.js `23.5.0`, without
installing a dependency tree or running lifecycle scripts. Offline regeneration
was byte-identical. npm's frozen dry-run accepted the matching manifest/lock pair
and rejected a version mismatch. A real new dependency installation has not been
performed by this change.

## External JavaScript dependencies

Use npm `10.9.2` and a dedicated, nonsynced external directory for this
manifest/lock pair. Confirm `npm --version` before installation. Set
`SWARX_JS_DEPS` to that absolute directory and `SWARX_NPM_CACHE` to an absolute
external download-cache directory. Both must stay outside the source checkout,
including after symlink resolution. Do not reuse another project's dependency
directory: `npm ci` replaces the dependency tree in its chosen prefix.

From the source root, validate the paths before copying inputs or installing:

```sh
set -eu
if [ "$(npm --version)" != "10.9.2" ]; then
  printf '%s\n' 'Setup requires npm 10.9.2.' >&2
  exit 1
fi
: "${SWARX_JS_DEPS:?Set an absolute external dependency directory}"
: "${SWARX_NPM_CACHE:?Set an absolute external npm cache directory}"
node --experimental-strip-types --input-type=module <<'JS'
import {ToolPathUtils} from './tools/utils/ToolPathUtils.ts';
ToolPathUtils.external(process.cwd(), 'SWARX_JS_DEPS');
ToolPathUtils.external(process.cwd(), 'SWARX_NPM_CACHE');
JS
mkdir -p "$SWARX_JS_DEPS" "$SWARX_NPM_CACHE"
cp app/package.json app/package-lock.json "$SWARX_JS_DEPS/"
npm ci --prefix "$SWARX_JS_DEPS" --cache "$SWARX_NPM_CACHE" \
  --ignore-scripts --no-audit --no-fund
export PATH="$SWARX_JS_DEPS/node_modules/.bin:$PATH"
```

This keeps `node_modules` and npm's download cache external, with no dependency
link or alias inside source. The checked-in manifest and lock remain source
inputs. With the required host-platform tarballs already cached, add `--offline`
to `npm ci`; otherwise npm fetches the registry URLs and verifies the integrities
recorded in the lock. Review package-manager or dependency changes deliberately,
then regenerate the lock with the real package manager. Do not edit dependency
graphs or integrity values by hand.

The explicit external `PATH` makes this dependency tree's `tsc` available to
source commands such as `./build.sh`. Run typechecks from source with the project
path, rather than running copied package scripts from the external prefix.

```sh
tsc --project app/client/jsconfig.json
```

## External build and launch paths

Set these environment variables to absolute paths outside the source checkout
before running `./build.sh` from the project root. The path check also resolves
existing ancestors to reject a symlink route back into the source checkout.
There are no machine-specific fallback paths. Choose designated nonsynced
build and cache directories: the guard checks that a path is outside this
checkout, not whether it is cloud-synchronized.

| Variable | Required value |
| --- | --- |
| `TACHYON_COMPILER` | An executable qualified Tachyon compiler. |
| `OBSERVATORY_NATIVE_ARTIFACTS` | External native output root, supplied to the compiler with `--out-dir`. |
| `OBSERVATORY_RUST_CACHE_PATH` | External Cargo build/cache root. |
| `OBSERVATORY_SWIFT_CACHE_PATH` | External Swift and Clang module-cache root. |
| `OBSERVATORY_ROLLBACK_ROOT` | External directory for preserving an existing app before rebuilding it. |

`CARGO_TARGET_DIR`, when supplied, is also honored and checked to remain outside
source. A relative value resolves from the project root; an absolute value is
used directly. When unset, Cargo output uses `target/` under the explicitly
configured `OBSERVATORY_RUST_CACHE_PATH`.

The build composes the Tachyon output, Rust companion, thin native host and
application icon. Its current native bundle is
`macos/SWARX.app` under `OBSERVATORY_NATIVE_ARTIFACTS`. Generated project inputs also remain under that external
root. The output route has source and fixture checks; this preparation did not
perform a new native build or launch.

For `./run-local.sh`, set `OBSERVATORY_APP_BUNDLE` to an existing external `.app`
directory. The launch entrypoint opens that bundle; it does not build one.

Installed dependencies, compiler binaries, caches, native bundles and all build,
test and preview artifacts must remain outside the source checkout permanently
and outside the public source inventory. Keep application state and opt-in event
records separate from build artifacts. A local artifact-routing launcher is a
machine setup detail; no personal launcher path belongs in portable source.

## Validation boundary

Source checks and native acceptance have separate prerequisites. Live QA requires
an external `OBSERVATORY_QA_ROOT` with a pre-created `evidence/` directory and an
existing `OBSERVATORY_APP_BUNDLE`. Explicit report fields are
`OBSERVATORY_QA_SESSION_ID`, `OBSERVATORY_QA_AGENT_ID`, `OBSERVATORY_QA_FAMILY`,
`OBSERVATORY_QA_SESSION_LABEL`, `OBSERVATORY_QA_TASK_ID`,
`OBSERVATORY_QA_TASK_NAME` and `OBSERVATORY_QA_ACTION_NAME`. Supply only real,
caller-owned context for a live check. The native lifetime check additionally
requires `OBSERVATORY_LIFETIME_EVENT_FILE`, an external JSON file containing a
real caller-owned report.

Offline browser QA requires explicitly selected external dependencies and
fixtures: `OBSERVATORY_PLAYWRIGHT_MODULE` (ESM entry),
`OBSERVATORY_BROWSER_EXECUTABLE`, `OBSERVATORY_WEB_BUNDLE`,
`OBSERVATORY_BUILD_SOURCE` (qualified source-hash manifest),
`OBSERVATORY_OVERVIEW_FIXTURE` (Rust fixture executable) and
`OBSERVATORY_QA_ROOT`. These generated artifacts are not included with public
source. No dependency installation or new native/browser runtime result is
claimed by this documentation.

A future native acceptance must check the renamed bundle, ordinary and small
window layouts, actual browser dependency resolution, polling focus/scroll,
charts, Help navigation and normal Quit. A source typecheck or fixture result
does not replace that acceptance. No web/HTTP target is part of this desktop
setup.

## Local data

Task events are explicit opt-in reports. Process links require a verified
process identity; resources without a proven session link remain separate.
Event adapters must send safe, already-sanitized action labels through the
supported private local boundary and retain source, stale and unavailable labels.
Do not send credentials, prompts, transcripts or terminal output. Supported
redaction is bounded; it does not guarantee removal of every secret format.
This document changes no storage path, IPC identifier or application-owned
collector lifecycle.


## Private candidate event directory on macOS

For concurrent native candidate verification, the optional process-local
SWARX_QA_EVENT_DIRECTORY selects a separate event directory. Supply it only in
the admitted candidate process environment. Do not set a persistent launchctl
variable or change the installed app's launch profile. An absent setting
preserves the normal per-user endpoint and state. Other platforms keep their
existing endpoint rules.

The selected directory must already exist, be empty, absolute, UTF-8, owned by
the current UID and mode 0700. Prefer a short physical path under /private/tmp.
The system /tmp alias is accepted; symlink routes below it, other aliases,
the installed directory and its descendants are rejected. The complete
hooks-native.sock path must fit the macOS Unix-socket capacity. The resolver
does not create or chmod a directory to make it acceptable.

The candidate uses hooks-native.sock, native.lock, roster-native.json and
session-bindings-native.json in that directory. Directory device/inode checks
cover startup, socket cleanup and descriptor-relative state I/O. Explicit
invalid configuration refuses event-source startup without a default receiver,
roster writer or listener. Native lifecycle capability remains unavailable.
Keep a failed or completed candidate directory as evidence; each configured
launch requires a fresh empty directory.

The helper default is unchanged. Every candidate delivery, including renewal,
unbind and finish, must pass --socket with the exact selected private endpoint.
Global hooks that omit it continue targeting the installed collector and are
not candidate evidence. Validate receipts and actual candidate listener identity.
Use independent native artifacts, caches and runtime ownership for the candidate.

These identity checks do not make pathname-based Unix socket binding/chmod
atomic against same-user directory replacement. Admission must preserve and
supervise the exact private directory and its physical route throughout the run;
unknown identity stops acceptance. Transport/state isolation does not isolate
OS sampling or grant permissions. The candidate bundle/window still needs exact
PID, birth, executable and window verification before Resources/Process Tree
actions. Source and regression preparation alone is not live UI qualification.
